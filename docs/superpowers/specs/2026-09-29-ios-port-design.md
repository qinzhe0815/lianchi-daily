# 练吃日课 iOS 迁移设计

用户授权新建分支并按自主节奏完成 iOS 版本。本次采用 Capacitor 8 原生 iOS 容器，保留现有规则引擎和五个页面，生成可用 Xcode 打开的工程。SwiftUI 全量重写会重复实现和验证规则，PWA 无法保留本地定时提醒，因此均不采用。

## 范围

- iPhone/iPad，iOS 15 起；保留安卓和浏览器的运行能力。
- 新增 iOS 原生工程、权限用途说明、隐私清单、图标、构建检查与自用安装说明。
- 平台服务集中在 platform.js：平台识别、通知排序和数量限制、原生拍照/选图、持久化与安全凭据。
- iOS 不执行 APK 更新；没有正式 App Store ID 时，清楚显示通过 Xcode/TestFlight 安装新版，不生成虚假商店链接。
- 资料、记录和外观仍通过同步接口读取，但原生启动前从原生原子快照文件恢复缓存；写入同步更新缓存并串行持久化。API Key 在 iOS Keychain 中保存，导出仅在明确选择包含接口时带出。
- AI 发送前按 HTTPS 接口和数据用途取得授权，拒绝后不发送。隐私页支持查看说明、撤销授权和清除本机数据。
- 通知按实际日期时间排序，iOS 最多 64 条；重新进入前台时补排。不能保证用户数周不启动仍有全量定时通知，文档明确说明。
- 拍照、照片选择、触感、分享使用 Capacitor；系统文件选择器负责备份导入。
- 键盘、安全区、减少动态效果和前后台状态均保留并验证。

## 数据兼容和错误处理

保留 lcd: 键名和备份格式；从旧 localStorage 迁移到原生存储，不删除旧数据直到原生写入成功。原生存储失败时显示可重试启动界面，不悄悄用空数据启动。恢复备份后等待持久化再重载。清除数据同时清除通知、原生存储、Keychain 和本地缓存。

## 验证

保留算法和原表对照测试；新增真实平台行为测试：iOS 不走 APK、通知数量/顺序、跨午夜日期、存储重启恢复、Keychain 迁移、失败保留旧记录、AI 授权和 HTTPS。执行 JavaScript 语法检查、iOS plist/项目结构校验。当前主机缺少完整 Xcode，不能声称已编译或已在真机验证；提供 macOS CI 的模拟器构建和逐项真机检查说明。
